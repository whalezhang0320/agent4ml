# Task Memory 在线三组对照评测结果

评测时间：2026-10-06（Asia/Shanghai）

## 结论

在本次 5 个案例、每个案例 16 轮的在线评测中，当前 `task_memory` 方案：

- 相对完整历史节省 **57.50% 输入 token**（少 517,925 token）；
- 相对旧摘要节省 **29.63% 输入 token**（少 161,186 token）；
- 相对完整历史减少 **8.68% 累计模型调用延迟**；计入本地治理开销后，端到端累计耗时减少 **4.72%**；
- 相对旧摘要减少 **16.51% 累计模型调用延迟**；计入本地治理开销后，端到端累计耗时减少 **13.01%**；
- 当前事实识别率 **100%**，跨轮历史事实召回率 **100%（60/60）**；
- 任务记忆的 160 条工具证据全部通过 Graph → Event → Ref 完整性校验。

最值得关注的是质量：旧摘要方案的跨轮历史事实召回率只有 **53.33%（32/60）**，当前方案为 **100%（60/60）**。当前方案的综合精确检查分数为 98.12%，低于完整历史的 100%，但丢失的 3 个检查全部是早期轮次没有遵守 `CARRY=NONE` 输出格式，而不是遗忘历史事实。

内部摘要调用同样使用上述模型、temperature 和最大输出配置，并计入 token、模型调用次数与耗时。`legacy_summary` 每个案例触发一次摘要，共增加 5 次模型调用；另外两组没有内部模型调用。

## 质量拆解

每轮检查两个值：本轮权威锚点，以及用户指定的历史轮次锚点（前 4 轮要求输出 `NONE`）。

| 方案 | 本轮事实 | 跨轮历史事实 | 前 4 轮 `NONE` 指令 | 综合精确分数 |
|---|---:|---:|---:|---:|
| 完整历史 | 80/80（100%） | 60/60（100%） | 20/20（100%） | 160/160（100%） |
| 旧摘要 | 80/80（100%） | 32/60（53.33%） | 17/20（85%） | 129/160（80.63%） |
| 当前方案 | 80/80（100%） | 60/60（100%） | 17/20（85%） | 157/160（98.12%） |

当前方案的 3 个失败均发生在 `incident_timeline` 第 2–4 轮：模型输出了上一轮的真实锚点，而不是按用户要求输出 `NONE`。因此这 3 项属于格式/指令遵循偏差，不能解释为任务记忆丢失。

旧摘要方案在第 11 轮压缩后集中丢失历史锚点：部分回答为 `UNKNOWN`，部分生成了证据中不存在的锚点。它的当前轮事实仍为 100%，说明主要损失位于摘要后的精确历史事实，而非读取当前证据。

## 验收结果

以下检查全部通过：

- 5 个案例、每案例 3 个组别；
- 每个任务恰好完成 16 轮；
- 主回答总数恰好为 240；
- 请求模型、temperature、最大输出和上下文窗口一致；
- 系统提示词哈希一致；
- 同一案例的用户问题哈希一致；
- 所有请求的实际输入 token 均未超过 24k；
- 240 个主回答均非空；
- 旧摘要方案的 5 个案例都实际触发了摘要；
- 当前方案 160 条证据全部通过持久化和可读取性校验。

## 解读边界

本次每个“案例 × 方案”只运行一次。temperature=0 能降低生成差异，但在线服务延迟仍会受到排队、缓存和网络影响。因此：

- token 节省和精确事实召回可作为本次最稳定的结论；
- 延迟数据适合看总体趋势，不适合把单案例百分比当作长期 SLA；
- 案例是受控的精确事实追踪任务，不能替代开放式研究、真实工具故障和超长任务的后续评测。
